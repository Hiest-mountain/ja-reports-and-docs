# 書いた後の点検

4 節で文を削って、5 節で内容と構成を直してから、最後に 6 節で文を仕上げる。5 節で書き足した文も点検の対象にするために、文の点検は最後に行う。

点検の候補は `lint.mjs` が列挙する。どの段階でも、書き手とサブエージェントは次のコマンドを実行して、出力された行を直す候補として扱う。

```
node lint.mjs 文書のファイル
node lint.mjs 文書のファイル --outline
```

`lint.mjs` は `SKILL.md` と同じフォルダにあるので、実行するときは絶対パスで指定する。1 つ目のコマンドは候補を 1 行に 1 つ出力して、最後に種類ごとの数を出力する。各行には行番号、候補の種類、当たった箇所、直し方が並ぶ。2 つ目のコマンドは節ごとに最初の文を出力する。当たった行は直す候補なので、直すかは `SKILL.md` の 3 節で判断して、悪い例として引用した箇所は対象外にする。`node` を実行できない環境では、6 節の末尾にある正規表現を Grep ツールで 1 つずつ検索する。

サブエージェントを起動できない場合は、4〜6 節の点検を書き手が自分で行う。自分がサブエージェントとして動作している場合もこれに当たる。自分で行うときは次の 4 つの操作を順に行う。どの操作もツールを実際に呼び出して行う。

1. `lint.mjs` を実行する。種類が「選別」「言い切りの連続」「冒頭」の行ごとに、その文が読み手の操作か判断を変えるかを決めて、変えない文は削る。文と箇条書きに重ねて書いた内容も削る。
2. `--outline` を実行して、出力された各節の最初の文を設計メモの「読み手の問い」と照合する。最初の文が問いに答えていない節は答えを先頭に移す。メモに無い節があれば、その節を削るか、メモに問いを書ける内容に直す。
3. 残りの種類の行を 6 節の表の直し方で直す。「順番」の行には `SKILL.md` の 3.6 の 2 つの判定を当てる。直す必要の無い行はそのままにする。
4. `lint.mjs` をもう一度実行して、直した箇所が候補から消えたことと、直した文が新しい候補になっていないことを確かめる。最後にファイルを読み直して、主体が分からない文と、根拠より強く言い切った文を直す。

書きながら確かめたことを理由にこの点検を省くと、経緯の文と重複と言いさしの読点がそのまま残る。削除した文の数、`lint.mjs` の候補の数、修正した箇所の数を報告する。

## 4. 削る役のサブエージェントに削らせる

ファイルに出力する文書では、文書を書いた Claude とは別のサブエージェントを起動して次の 3 つを渡す。

- 文書のファイルパス
- 設計メモ
- `SKILL.md` の 1 節

サブエージェントには編集者として文を削ることとまとめることだけを依頼する。

| してよいこと | してはいけないこと |
|---|---|
| 文を削る | 事実を足す |
| 同じ行動を求める複数の文を 1 つにまとめる | 節を足す、見出しの順番を変える |
| まとめるために語を言い換える | コードブロックと番号付きの手順の中身を変える |
| | 「だけ」「未確認」「推定」など、限定と確度の語を削る |

書き手は、削った文とその理由をサブエージェントに報告させて確かめる。前後の文脈が無いと意味が伝わらない事実は、正しくても削ったままにする。

## 5. 読み手役のサブエージェントに読ませる

README と手順書と PR の説明では、削る役とは別のサブエージェントを起動して文書を読ませる。そのサブエージェントには文書のファイルパスだけを渡して、次の 7 つを質問する。設計メモは渡さない。悪い例として載せた箇所があれば、指摘の対象から外すように伝える。

1. これは何をするもので、読んだ後に最初に何をするか
2. 節ごとに、その節を読んで分かったことか、できるようになったことを 1 行で書く。何も無い節は「無い」と書く
3. 意味を一つに決められなかった語と、主体が分からなかった文はどれか
4. 表のセルや箇条書きだけを読んで、何を誰が行うのかが分からなかった箇所はどれか
5. 読みにくい文、不自然な文、AI が書いたように感じる文はどれか
6. 見出しと内容が合っていない節はどれか
7. 探したが見つからなかった情報は何か

1 の回答を設計メモの「読んだ後にすること」と、2 の回答を「読んだ後に分かること、できること」と 1 行ずつ照合して、食い違う節を直す。「無い」と書かれた節は削るか、内容を問いの答えに直す。7 の回答のうち元の資料に無い情報は、依頼者に確認する。

指摘に答えるときは、すでにある文を具体的にして疑問を解く。文を足すなら、足す文に `SKILL.md` の 3.6 の 2 つの判定を当てる。「操作は要りません」「〜ではありません」のように否定の文で疑問に答えると、誤解を止める必要の無い文が増える。

直した後に冒頭の段落が 3 文を超えていたら、起動方法のほかの文を後ろの節へ移す。

## 6. 文を 1 文ずつ点検する

点検は文書の内容が固まった後に、別のサブエージェントに任せて行う。文書を書いている Claude は自分の書き癖のまま書くので、書きながらでは 3 節の規則を守りきれない。

ファイルに出力する文書では、4 節と 5 節とは別のサブエージェントを起動する。そのサブエージェントに文書のファイルパスと `SKILL.md` の 3 節を渡して、次のように依頼する。

- 地の文を 1 文ずつ取り出して、文ごとに次の 6 つを確かめる。表や例に載っていない語と構造にも 3 節の基準を適用する。
  1. ソフトウェアの動作か利用者の操作を意味の広い和語の動詞で書いていないか（3.2）
  2. 長い修飾が主題と述語の間や名詞の前に重なっていないか。文末が「〜する A です」の形になっていないか（3.4）
  3. 読点が 3.5 の位置に打たれているか
  4. 主語と目的語が読み手に分かるか（3.3）
  5. 事実を 1 つずつ言い切った短い文が 3 つ以上続いていないか。続いていれば、理由か条件か結果の関係にある文をつなぐ（3.4）
  6. 否定、例外、以前の姿との比較を含む文に、3.6 の 2 つの判定を当てたか。削れる否定は削り、先に置く必要のない否定は後ろに回す（3.6）
- 段落ごとに、読み手がそこで最初に知りたいことと、冒頭の文が答えていることを 1 行ずつ書き出す。2 つが合わない段落は、読み手が最初に知りたいことを先に置く（3.6）
- 最初に `lint.mjs` を実行して、出力された候補を下の表の直し方で直す。その後で、スクリプトが検出できない次の点を 1 文ずつ確かめる。
- 報告には修正した箇所だけを載せて、修正前と修正後の文を対にして示す。事実を足すことも削ることもしない。

書き手は一覧を確かめる。サブエージェントを起動しない文書では、書き手が同じ点検を自分で行う。

`node` を実行できない環境では、次の正規表現で検索する。上から順に、読点、語、文の型、選別の候補、敬体の文書に混ざった常体、常体の文書に混ざった敬体、3.6 の判定を当てる候補を探す。4〜7 つ目は、サブエージェントを起動しない場合の操作 1 と操作 4 で使う。当たった行は直す候補で、当たったことは直す理由にならない。検索は Grep ツールで行う。Git Bash や PowerShell の grep は日本語の文字クラスを 1 バイトずつ照合するので、該当しない行まで検出する。

```
[しりれけえ]、|[はもをにの]、
始ま|並[ぶびべん]|選[ぶび]|試[すし]|入れ|置[くいき]|直[すし]|見比べ|動か|立て|起こ|当て|詰め|写[すし]|回[すし]|落と|物|所|形|感じ|辺り
のは|ことを目的|次の|以下の|定め|ではな[いく]|でなく|とは違う|作者|私|僕|自分は|手元|前回|今回|さっき|→|—|\*\*|(もの|仕組み|ツール|スクリプト)(です|である)|分かったこと(です|である)|次のとおり|^\s*([-*]|[0-9]+\.) [^:：\s`]{1,10}[:：]
たところ|た(ため|ので)|ていたため|想定して|設けている|以前は|当初|事故|[0-9]+ ?(件|ファイル|GB|MB|分|秒|回)[^。]*確認|ためのもの|照らして|判断してください|例がある|ことがある
^[^|\-\s#>`*0-9].*(である|ている|[^まわ]ない|[^まで]した|になる)。
^[^|\-\s#>`*0-9].*(です|ます|ました|ません)。
[代か]わり(に|として)|のではなく|ではなく|でなく|せず(に|、)|ないで、|従来は|これまでは|もともと|既定では|[だて]ったが、
```

当たった行は下の表の直し方で直す。悪い例として引用した箇所と語の一部に当たっただけの箇所は対象外にする。「形式」の「形」と「直接」の「直」と「前回」の「回」は、語の一部に当たっただけの例である。

| 検索する語 | 当たった文の直し方 | 節 |
|---|---|---|
| 始ま、並、選ぶ、選び、試、入れ、置、直、見比べ | ソフトウェアの動作か利用者の操作を表していれば、3.2 の表の語に置き換える | 3.2 |
| 動か、立て、起こ、当て、詰め、写、回、落と | 意味ごとに一つに決まる語へ置き換える。「動か」は 3.2 の表の語を使う | 3.1、3.2 |
| 物、所、形、感じ、辺り | 指している対象の名前に置き換える | 3.1 |
| 「は、」「では、」「には、」「も、」 | 短い文なら読点を消す | 3.5 |
| 「の、」「を、」「に、」 | 修飾と名詞の間か、目的語と動詞の間の読点なら、語順を変えて読点を消す | 3.4、3.5 |
| 「し、」「り、」など、動詞を言いさした直後の読点 | 当たった箇所は全部直す。「入り、」は「入って」、「返し、」は「返して」のように「〜して」の形に変えるか、文を 2 つに分ける。前後が長ければ「〜して、」と読点を残してよい。「あり、」「であり、」は文を分ける | 3.5 |
| 読点が 3 つ以上ある文 | 文を分けるか、列挙を箇条書きに移す | 3.5 |
| 「のは」「ことを目的」 | 要点を文末に置いているか動作を名詞に包んでいれば、動作を述語にする | 3.4 |
| 「次の」「以下の」「定め」 | 中身を予告しているだけの文なら消して、中身を書く | 3.4 |
| 「Claude は」「この skill は」で始まる文、「します。」で終わる文 | 3 文以上続けば、主語を省くか、理由で前の文につなぐ | 3.3、3.4 |
| ではない、ではなく、でなく、とは違う | 否定の側を消しても意味が通るなら消す | 3.6 |
| 作者、私、僕、自分は、手元 | 作者の環境や経緯を述べていれば、読み手にとっての意味に書き換える | 3.7 |
| 前回、今回、さっき、内部の番号 | 説明を付けるか消す | 3.8 |
| `→` `=` `/` `—`（地の文） | 関係を語で書く | 3.4 |
| `**`（1 段落や 1 つの箇条書きに 2 箇所以上、箇条の先頭の `**ラベル**:`） | 太字を外して文にするか、表にする | 3.4 |
| 箇条の先頭の「ラベル:」（「- 役割: 〜」「1. 設定の平文パスワード: 〜」） | ラベルを外して文にするか、ラベルを列にした表にする | 3.4 |
| 「〜から分かったことです」「次のとおりです」 | 中身を予告しているだけの文なら消して、中身を書く | 3.4 |
| 「〜するツールです」「〜する仕組みである」など、名詞で終わる文 | 名詞の前の修飾が長ければ、主題を立てて動詞で終える | 3.4 |

依頼者に不自然だと言われても原因が分からないときは、人が書いた同じ種類の文書を 3〜4 本集める。集めた文書と点検中の文書の両方で主語と文末と理由のつなぎ方を数えて、その数を比べる。
